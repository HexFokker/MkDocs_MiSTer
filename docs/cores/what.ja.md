MiSTer の用語でコアとは、特定のシステムや機能を提供する FPGA 設計のことです。ほとんどのコアはコンソール・コンピューター・アーケードシステムを実装しますが、Menu コアはユーザーインターフェイスを提供します。デフォルトでは電源投入時に Menu コアが読み込まれます。`_Console` メニューで `NES` などのコアを選ぶと、FPGA はそのコアの設計で再設定されます。

ハードウェア記述言語（HDL）の開発者は、FPGA に書き込まれるもの全般を「コア」と呼びます。たとえば MiSTer FPGA フレームワークは Intel の "Altera PLL Core" を使っています。これは開発者がチップのクロック速度を設定できる、再利用可能なロジックブロックです。HDMI コア、Ethernet コア、シリアルデータコアなどがあります。

たとえば、[PSX（PlayStation）コア](https://github.com/MiSTer-devel/PSX_MiSTer){target=_blank}、[Minimig（Amiga）コア](https://github.com/MiSTer-devel/Minimig-AGA_MiSTer){target=_blank}、[SNES コア](https://github.com/MiSTer-devel/SNES_MiSTer){target=_blank}など多数あります。

## コアを読み込むと何が起きる？

コアを読み込むたびに、別のコンソール・コンピューター・アーケードシステムをテレビに繋ぎ替えていると想像してください。メニューで MegaDrive コアを選んで読み込むと、ケーブルを繋ぎ直す手間なく、実質的に Mega Drive をテレビに接続したことになります。実際に起きているのは、`.rbf` ファイルが FPGA チップを再プログラムすることです。NES 用のデジタルロジックが Mega Drive 用のデジタルロジックに置き換わります（どちらも MiSTer フレームワークのロジックと結合されます）。

この繰り返しの書き換えが FPGA の寿命を縮めるのでは、と心配になるかもしれません。心配は無用です。コアを読み込み替えても flash のプログラム/消去サイクルで FPGA を消耗させることはありません。コンフィギュレーションは SRAM に保持され、別のコアを読み込むときにそのまま置き換わるだけです。

## コアの更新と不具合

MiSTer のコアは、長年にわたり複数の先行オープンソースプロジェクトをまたぐ、多くの人々のコラボレーションの成果です。精度・機能網羅・既知の問題はコアによって異なります。セットアップ要件・対応機能・既知の制限は該当コアの README と issue トラッカーを確認し、新しい issue を立てる前に既存の issue を検索してください。

コアリポジトリーの一覧は [MiSTer FPGA GitHub Organization](https://github.com/MiSTer-devel){target=_blank} を参照。各コアのページから、リリースフォルダー、Issues ページ、README（理想的にはそのコアの全機能と制限が詳しく記載されています）へ辿れます。

MiSTer-devel 組織外で独立して管理されているコアはここには載せていません。インストール手順やサポート窓口が異なる場合があるため、それぞれのドキュメントを確認してください。
