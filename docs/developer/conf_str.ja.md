MiSTer はキーボードの F12（または OSD ボタン）でトグルできるオンスクリーンディスプレイ（OSD）を提供します。読み込まれたコアごとに、このメニューにそのコア専用のオプションを追加するよう設定できます。

コアのトップレベルモジュールは `emu` です。これは `emu` がプロジェクトのトップレベルモジュールという意味では**ありません**。コアの視点でのトップレベルです。`emu` モジュールは通常、プロジェクトと同名の SystemVerilog ファイル（`*.sv` 拡張子）にあります。例として、Arcade-Galaga プロジェクトのトップレベルモジュールは `Arcade-Galaga.sv` にあります。

設定文字列は `emu` モジュールの `CONF_STR` 変数に格納されます。この変数は `hps_io` モジュールに渡され、プロセッサーに送られて必要なときに読み込まれます。設定文字列の各行はセミコロンで区切られます。

## ステータスビットマップ

ほとんどのコアは `CONF_STR` セクションの先頭にステータスビットマップを持ちます。開発者は、どのステータスビットが使用中かを示すためにこれを更新します。コア開発時にはこれを使ってください。コラボレーションに役立つ重要な参照だからです。1つのオプションしか1つのステータスビットを占有できないため、重要です。ステータスビット `[0]` はソフトリセット用に予約されています。

たとえば何も使用中でない場合：

```
// Status Bit Map:
//             Upper                             Lower              
// 0         1         2         3          4         5         6   
// 01234567890123456789012345678901 23456789012345678901234567890123
// 0123456789ABCDEFGHIJKLMNOPQRSTUV 0123456789ABCDEFGHIJKLMNOPQRSTUV
// 
```

`O89` のようなステータスビットオプションをコア設定文字列に追加すると、オプションを示す "O" が大文字なので（Upper とマークされている）、左側の最初のステータスビットグループを使います。次に下の行（英数字）の 8 と 9 を使います。使用後はインデックスを更新してください：

```
// Status Bit Map:
//             Upper                             Lower              
// 0         1         2         3          4         5         6   
// 01234567890123456789012345678901 23456789012345678901234567890123
// 0123456789ABCDEFGHIJKLMNOPQRSTUV 0123456789ABCDEFGHIJKLMNOPQRSTUV
//         XX
```

これは他の開発者に `status[9:8]` が使用中で使うべきでないことを伝えます。

## メニューで有効なオプション

`[]` - オプションパラメーターを意味します

* `C[,{Text}]` - `{Text}` ラベルのチートメニューエントリーを有効化。
* `CHEAT` - DIP と同様、チートシステムのあるアーケード向け
* `D{Index}` - `menumask[Index]` がセットされている場合にオプションを無効にするプレフィックス。
* `d{Index}` - 'D' と同じだが、`menumask[Index]` がセット**されていない**場合にオプションを無効にする。
* `DIP` - アーケードコアで、MRA の DIP メニューを表示する
* `F[S][#],{Ext}[,{Text}][,{Address}]` - ファイル読み込みボタン。 
    * `{Ext}` - 3文字のファイル拡張子を連結したリスト。たとえば `BINGEN` は `BIN` と `GEN` 拡張子です。
    * オプションの `{Text}` は拡張子の前に表示されるテキストで、"Load RAM" など。`{Text}` を指定しない場合、デフォルトは "Load \*" です。
    * オプションの `[S]` - コアがセーブファイルに対応。ファイルを読み込み、読み書き用のセーブをマウントする
    * `#` は明示的なインデックス（指定しない場合、インデックスは行番号から生成）。
    * オプションの `{Address}` - ファイルをこのアドレスの DDRAM に直接読み込む
    * hps_io からの ioctl_index は：ioctl_index[5:0] = index（明示的または自動）、ioctl_index[7:6] = 拡張子インデックス
* `FC[#],{Ext}[,{Text}][,{Address}]` - ファイルを開いて記憶。代替 ROM、設定、その他のファイルを覚えておくのに便利。オプションの仕組みは `F` を参照。

* `H{Index}` - `menumask[Index]` がセットされている場合にオプションを隠すプレフィックス。
* `h{Index}` - `H` と同じだが、`menumask[Index]` がセット**されていない**場合にオプションを隠す。
* `O{Index1}[{Index2}],{Name},{Options...}` - さまざまな選択肢から選べるオプションボタン。
    * `{Index1}` と `{Index2}` は 0-9 と A-V の値（hex に似ているが A-F ではなく A-V まで拡張）。これは全31ビットを表します。1つ目と2つ目のインデックスは、ステータスレジスターにセットされるビットの範囲です。
    * `{Name}` はオプションを説明するために表示されるもの。
    * `{Options...}` - カンマ区切りのオプションのリスト。
* `P{#},{Title}` - `{Title}` というオプション用サブページを作成。
* `P{#}` - オプションを特定の `{#}` ページに配置するプレフィックス。`O#` の前だが `d#` のようなものの**後**に追加します。（`"d5P1o2,Vertical Crop,Disabled,216p(5x);"` は正しく、`"P1d5o2,Vertical Crop,Disabled,216p(5x);"` は不正でメニューオプションが動きません。）
* `R{Index},{Name}` - `T` オプションと同じだが、選択後に OSD を閉じます。リセットオプションに便利です。
* `S{Slot},{Ext}[,{Text}]` - SD カードマウントボタン。 
    * `{Slot}` - 0-3 の値。最大4つのイメージを同時にマウントできます。
    * `{Ext}` - `F` オプションと同じ。
    * （オプション）`{Text}` - "Load RAM" のような拡張子の前に表示されるテキスト。`{Text}` を指定しない場合、デフォルトは "Mount \*" です。
* `T{Index},{Name}` - トリガーボタン。ステータスレジスター内の指定した `{Index}` ビットを HIGH にパルスするシンプルなボタン。リセットボタンが完璧な例です。
    * `{Name}` はボタンの機能を説明するテキスト。
* `-[,TEXT]` - 空行（または `TEXT` 付きの行）。
* 小文字オプション `o`、`t`、`r` は、ステータスビットインデックスに 32 を加えた大文字バリアントと同等です。

## 非 OSD オプション

これらは設定文字列の末尾に配置する必要があります：

* `J[1],{Button1}[,{Button2},...]` - J1 はキーボードをジョイスティックエミュレーションモードにロック。コンソールのようなキーボードなしシステムに便利です。{Button1},{Button2},... はコアで使うジョイスティックボタンのリスト。最大12ボタンまで列挙できます。アナログ軸はここでは定義しません。ユーザーは Menu コアでマッピングするだけです。
* `jn,{SNES Button Name1},[,{SNES Button2},...]` - ボタンのデフォルトマッピングを設定。例：`jn,A` はジョイスティックビット4を SNES スタイルコントローラーの A ボタンに自動マッピング
* `jp` - `jn` と同じだが、`MiSTer.ini` で `gamepad_defaults=1` の場合に使用。通常は SNES コントローラーに対する位置マッピングを指します
* `V,{Version String}` - バージョン文字列。コア名を取り、コア読み込み時に表示される名前にバージョン文字列を付加します。コアブラウザー（コア読み込み前）のタイムスタンプは `Version String` 由来ではなく .rbf ファイル名由来であることに注意。
* `I,INFO1,INFO2,...,INFO255` - OSD 情報（画面左上）として表示する `INFO1-INFO255` 行。
* `DEFMRA,{mra name}` - コアが USB Blaster 経由でアップロードされたとき（デバッグ）に使うデフォルト MRA（例：Puckman.mra）

## jn と jp の違いとマッピング慣例

`jn` マッピングがデフォルトで、`jp` マッピングは INI ファイルに `gamepad_defaults=1` がある場合に使われます。両者は「哲学」、つまりボタンをマッピングする慣例だけが違います。`jn` はボタン**名**でマッピングし、`jp` はボタン**位置**でマッピングします。

どちらも MiSTer の内部ゲームパッドを参照します。Menu コアでは、すべてのコントローラーがこの内部 SNES スタイルゲームパッドにマッピングされます。そのボタンは ABXYLR + Start + Select の順（ボタン1 = A、ボタン2 = B、以下同様）です。

* **`jn`（名ベース）：** コアの A ボタンを内部 "SNES A" ボタンに、B を "SNES B" に、というように、名前（または順序）が元の SNES 定義（ABXYLR など）に一致するようマッピングします。コアに "A" という名前のボタンがなければ、その最初のボタンがそのスロットを取り、2番目のボタンが "SNES B" を取る、以下同様です。
* **`jp`（位置ベース）：** 各ボタンを物理的な位置でマッピングします。ボタン A、B、C を持つ Genesis 3ボタンコントローラーなら、マッピングは "SNES Y, SNES B, SNES A" になります。Y、B、A が SNES ゲームパッドの下側3ボタンだからです。
