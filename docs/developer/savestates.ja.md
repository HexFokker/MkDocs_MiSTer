MiSTer は高速なセーブステート保存・読み込みのための特別な API を定義しています。コアでセーブステート機能を有効にすると、開発者が指定した DDR3 メモリーのセクションが確保され、高速なセーブステート読み書きに使われます。プロジェクト内のすべてのレジスターとメモリーの実際の保存・読み込み機能は提供**しません**。

**注意：** MiSTer は現在ファームウェア上で正確に4つのセーブステートスロットに制限されています。この API でスロットを追加することはできません。

## セットアップ

[コア設定文字列](conf_str.md)で規定されているように、コア名定義の後に `SS{base addr}:{savestate size}` を続けられます。これはコアがセーブステートを使うことを宣言します。例：`MyCore;SS3E000000:1000;`。これはセーブステートが `0x3E00_0000` から始まり、それぞれ `0x1000` _バイト_ 割り当てられることを宣言します。ディスク上のセーブステートの実際のサイズはこの割り当てサイズと一致する必要はなく、それ以下であればよいです。セーブステートスロット1〜3がきれいなアドレスから始まるよう、2のべき乗を選ぶとよいでしょう。

**注意：** さまざまな MiSTer プロジェクトのほとんどの DDR コントローラーは、MiSTer フレームワークと CPU に十分な余地を残すため、アドレスを `0x3000_0000` 台にハードコードしています。

## 使い方

各セーブステートブロックの最初の64ビットワード（例での `0x0`、`0x1000`、`0x2000` など）は2つの32ビット値を含みます。下位32ビット（`[31:0]`）は変更検出器として機能し、上位32ビット（`[63:32]`）はセーブステートのサイズを格納します。

### 変更検出器

変更検出器は、セーブステートが更新されディスクに保存する必要があることを MiSTer ファームウェアに通知します。保存は書き込み発生後かなり速く行われ、ブロックデバイス保存のように OSD を開く必要はありません。この値はセーブステート書き込み処理の一部としてディスクに永続化されますが、再読み込みされず、コアの再起動や新しい ROM の読み込み時に `0xFFFF_FFFF` にリセットされます。

### セーブステートサイズ

セーブステートサイズワードは、最初の64ビット制御ワードを除き、セーブステートとして読み込むべき32ビットワード数を定義します。たとえば64バイトを取得するには、この値を `64 / 4 = 16` に設定します。この値はスロットごとに独立しているため、4つのセーブステートスロット間で変えられます。

コアが起動したとき、使用中のスロットはサイズワードが設定され、そのメモリーには現在のファイル内容が入っています。空のスロットは 0 に初期化されます。

### 実際のデータ

最初の64ビットの制御データの後、`CONF_STR` で定義した `savestate size` までの残りのアドレス空間は自由に使えます。空間全体を好きに読み書きできます。データは設定された制御サイズに従い、最初のワードが変わったときだけ永続化されます。この空間は、そのスロットにセーブステートファイルがある場合のみ初期化され、それ以外はランダムなデータが入ります。セーブステートサイズワードで示されたデータのみが永続化されることを忘れないでください。

### ディスク上のデータ

ディスクに永続化されるファイルは、32ビットワードで `savestate size control value + 2` です。つまり、実際のセーブステート内容のサイズに、ブロック先頭の制御データ用の追加64ビットを加えたものです。
