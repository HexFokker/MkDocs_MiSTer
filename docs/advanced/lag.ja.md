レトロゲーム愛好家の間でよくある懸念は、MiSTer のような機器に_ラグ_があるかどうか、そして実機より体験が劣るかどうかです。

すべての電子機器には何らかの_レイテンシー_があります。60 Hz ディスプレイでは1フレームは約 16.67 ms です。レイテンシーはフレームが目に見えて落ちる前から問題になり得ます。タイミング重視のゲームプレイに影響し、プレイヤーや機器間で異なることがあります。

ラグが問題になるのは、いくつかの特定のケースだけです：

* 極端に速い応答時間を前提に設計された古いゲームがある（例：NES の Punch-Out）。
* 2人のプレイヤー間でレイテンシーが違うと、不公平な有利になり得る。
* 一定でないラグは、精密な操作を要求するゲームで問題になることがある。（多くのプレイヤーは一貫したラグには適応できます。）

ラグのより詳しい概要は [https://inputlag.science/](https://inputlag.science/){target=_blank} を参照。

## ラグの発生源

ラグには3つの大きな分類があります。**入力**（コントローラー、マウスなど）、**処理**（コア内のバッファリング、コードの実行や遅延）、**表示**（ディスプレイ機器への映像出力）です。

### 入力
入力には、MiSTer は主に USB を使います。この場合、全体の入力ラグは USB ポーリングによるラグと、コントローラー自体のラグ（信号をどれだけ速く処理するか）の合計です。後者は MiSTer の範囲外で、より良いコントローラーを使うことでしか改善できません。MiSTer 側で減らせるのは USB ポーリングによるラグだけで、それも接続した USB 機器がより低いポーリング間隔に対応している場合に限ります。ポーリング間隔は Hz で測られ、USB 機器が毎秒何回ポーリングされるかを示します。1000 Hz ではポーリングは最大 1 ms（平均 0.5 ms）のラグしか加えません。125 Hz では最大 8 ms（平均 4 ms）加わります。

USB ポーリングは垂直同期とは独立して行われます。独立した一様サンプリングを仮定した大まかなモデルでは、入力がフレーム境界後に来る推定確率は、1 ms で約 1/16、8 ms で約 50% です。これは近似であり、実際の挙動はコントローラー・コア・ゲームによって異なります。

### 処理
処理は FPGA エミュレーションが大きな利点を持つ領域です。ほとんどのソフトウェアエミュレーターは、仕事を一括処理してから次の画面更新まで待機します。FPGA コアは一般にエミュレート対象のハードウェアと同期して連続動作するため、CPU 予算でボトルネックにはなりません。ただし一部のコアは独自の内部バッファリングを使います。

### 表示
MiSTer の主な表示出力はアナログと HDMI の2つです。

アナログ出力経路は非常に低いバッファリングで動作できるため、実機に近いレイテンシーになり得ます。ただしすべての構成で実機と同一のシステムレイテンシーが保証されるわけではありません。

HDMI 出力はスケーラーを通るため、処理レイテンシーが加わります。スケーラーが加えるレイテンシーは `vsync_adjust` 設定によって変わり、約4〜30ラインから最大約2フレームまでです（後述の[映像ラグ](#video-lag)を参照）。

テレビやモニターがさらにレイテンシーを加えることがありますが、機器によって異なるため、ここでは確定的な数値を出せません。

### まとめ

ラグが重要なら、**推奨され広くテストされた USB コントローラーで CRT 上でプレイするのが最良です。** ユーザーによって USB コントローラーの性能テストとランキングが行われています。その[結果](https://github.com/eniva/MisSTer_Guides/wiki/USB-Controllers-Performance-Ranking){target=_blank}をご覧ください。もう一つの網羅的なテスト済みコントローラーリストは、MiSTerAddons と Lemonici による [MiSTer Input Latency Chart](https://rpubs.com/misteraddons/inputlatency){target=_blank} です。

とはいえ HDMI 経由でも、MiSTer は他の多くの機器より良い体験を提供できます。

## ラグを減らす

### 映像ラグ { #video-lag }

SD カード直下の `MiSTer.ini` の `vsync_adjust` オプションは HDMI アップスケーラーを設定し、互換性とレイテンシーをトレードオフします：

* `vsync_adjust=2` はテレビが対応していれば最良の選択です。コア本来のリフレッシュレートとピクセルクロックを使い、サブフレームレイテンシーを実現します。スケーラーを作った Grabulosaure 氏によると、実際のレイテンシーは `vscale_mode=1` で約4〜30ライン、他のモードではもう少し増えます（[動画](https://www.youtube.com/watch?v=DYfUZ6PG7H4){target=_blank}）。
* `vsync_adjust=1` は2番目に良い選択で、1フレームのレイテンシーです。フレームバッファーを使いますが、システム本来の vsync を保ち、コアごとにピクセルクロックを変化させます。
* `vsync_adjust=0` はレイテンシー面では最も弱い選択ですが、最も互換性があります。最大1〜2フレームのレイテンシーで、スクロールがわずかに滑らかでなくなります。設定した `video_mode` のタイミングをそのまま出力するため（標準的なピクセルクロックとリフレッシュレート）、モダンディスプレイとの互換性が高いです。ただしコアのリフレッシュレートがディスプレイと一致しないため、時折のジャッターに気づくでしょう。

### 入力ラグ

USB コントローラーは通常ポーリング間隔を報告し、ホスト（MiSTer の Linux カーネル）は入力をポーリングする際にそれを尊重します。多くの USB 機器はより速いポーリングに適切に応答しますが、結果は機器によって異なります。

USB ポーリングレートを上げるには、SD カードの `linux` フォルダーで `u-boot.txt_example` を `u-boot.txt` にリネームします。ファイルには次のオプションが含まれます。高速ポーリングで特定の機器に問題が起きた場合は、デフォルトに戻すか間隔値を大きくしてください：
```bash
v=loglevel=4 usbhid.jspoll=1 xpad.cpoll=1
```
**loglevel**: 4 がデフォルト値。9 に設定すると SSH 経由で `dmesg` コマンドのデバッグメッセージが得られます。コントローラーに適用された jspoll/cpoll 値の確認方法は後述。

**usbhid.jspoll**: USB HID コントローラー（通常 DirectInput）の間隔を指定。

**xpad.cpoll**: USB XInput コントローラーの間隔を指定。XInput は Microsoft の Xbox コンソールと PC のコントローラー標準で、人気コントローラーの多くが使っています。値の意味は `usbhid.jspoll` と同じです。

両パラメーターは同じ値を取ります：

* `0` — デフォルト。コントローラーが要求した値が使われます（`u-boot.txt` がなくても同様）。
* `1` — 推奨。1000/1 = 1000 Hz ポーリング。問題が起きたらより大きな整数値を試してください。間隔が大きいほどラグの可能性も増えます。8（1000/8 = 125 Hz）を超えないでください。

適用された値を確認するには、Linux シェルで `systool -m usbhid -A jspoll` または `systool -m xpad -A cpoll` を実行します。

## 最速のコントローラーは？

ほとんどの標準 USB コントローラーは MiSTer で良好に動きますが、ユーザーのフィードバックと入力ラグテストに基づく優れた選択肢：

* 有線モードで接続した 8BitDo M30 2.4G
* 有線モードの Sony DS4
* Hori Fighting Commander（後期リビジョン）。PS4 または Xbox One バリアントのお好みの方を
* [こちら](https://github.com/MiSTer-devel/Retro-Controllers-USB-MiSTer){target=_blank}にあるオープンソースファームウェアを使った自作 USB アダプター

Bluetooth 接続の機器は一般に問題なく動きますが、有線接続よりレイテンシーが増えることが多いです。程度は機器によって異なります。

「高レイテンシー」のコントローラーでも、加わるラグは*高々*16 ms（1/60秒、1フレーム）か、まれにコントローラーによっては 32 ms で、しかも常時ではないことに注意してください。それほど大きくないので、ラグに気づかないなら、まともな USB コントローラーなら何を使っても問題ありません。可変のラグ（たとえば応答が1〜3フレームで変動）は、一貫したラグより気になります。1フレームを超えるラグを加えるコントローラーはごく少数です。

唯一無二の「最速コントローラー」はありませんが、トップに近いものはかなりあります。コミュニティ調査による確定的なリストは、MiSTerAddons と Lemonici の [MiSTer Input Latency Chart](https://rpubs.com/misteraddons/inputlatency){target=_blank} を参照。コントローラーは DE10-Nano のヘッダーに繋いだ別機器で MiSTer 上でテストされており、客観的な結果です。
