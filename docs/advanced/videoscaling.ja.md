MiSTer には内蔵スケーラーがあり、コアの低解像度映像を高解像度に変換し、オプションでフィルターを使ってモダンディスプレイでの見栄えを改善します。このページではスケーリングオプションの設定方法を説明します。

## Video Scale Mode（vscale_mode）

microSD カード直下の [MiSTer.ini ファイル](https://github.com/MiSTer-devel/Main_MiSTer/blob/master/MiSTer.ini){target=_blank}が、コアの元の映像をディスプレイへどうスケーリングするかを制御します。ファイルの先頭近くにこう書かれています：

```ini
vscale_mode=0          ; 0 - scale to fit the screen height.
                       ; 1 - use integer scale only.
                       ; 2 - use 0.5 steps of scale.
                       ; 3 - use 0.25 steps of scale.
                       ; 4 - integer resolution scaling, use core aspect ratio
                       ; 5 - integer resolution scaling, maintain display aspect ratio
```

それぞれの意味：

### vscale_mode=0（ディスプレイの高さに縦フィット）

MiSTer 初回起動時のデフォルトです。ゲーム解像度が 256x224 の場合、1920x1080p ディスプレイに縦に合わせるには 1080 を 224 で割りますが、割り切れません（`1080 / 224 ≈ 4.82`）。そのため一部のピクセルが均等にスケールされないことがあります。画面上から下まで完全に埋まるので気にしない人もいます。きらめくピクセル（シマリング）が見える場合は、補間ビデオプリセットかアダプティブスキャンラインフィルターで緩和してください。

### vscale_mode=1（整数スケーリング）

コアの映像出力の最終スケール倍率を整数（2x、3x、4x、5x、6x など）にします。`#!ini video_mode` が 1920x1080p の場合、先ほどの 256x224 の例は4倍にスケールされ（`4 * 224 = 896`）、残りは黒帯になります。ただしピクセルは正しくスケールされるので、（ディスプレイ側の問題でない限り）シマリングは出ないはずです。ピクセルが最もシャープで、望ましくない映像アーティファクトの可能性がずっと低いと好む人がいる一方、0 のように画面を埋めないのが嫌な人もいます。

### vscale_mode=2 と 3（分数スケーリング）

`#!ini vscale_mode=1` に似ていますが、整数刻み（2x、3x、4x など）ではなく、0.5 刻み（2x、2.5x、3x、3.5x、4x）または 0.25 刻み（2x、2.25x、2.5x、2.75x、3x）でスケールします。シャープなフィルタリング（またはフィルターなし）を使いながら、一部のモニターでシマリングを大きく減らせます（すべてではありません）。コアごとに `vscale_mode=2` と `3` を試して最良の見た目を見つけてください。

### vscale_mode=4 と 5（動的スケーリング映像モード）

wickerwaka 氏が追加したこれらのモードは、`#!ini video_mode` を動的に変更し、画面を埋めたまま整数スケーリングを維持します。2560x1440p や 4K ディスプレイで理想的で、ほぼゼロのシマリングと映像アーティファクトで縦方向に画面を埋められます。仕組みを学びたくなければ、設定して試すだけで構いません。

#### vscale_mode=4（コアのアスペクト比を使う整数解像度スケーリング）

[MiSTer.ini ファイル](https://github.com/MiSTer-devel/Main_MiSTer/blob/master/MiSTer.ini){target=_blank}で `#!ini video_mode=13` を設定した場合、MiSTer にディスプレイを 60 Hz リフレッシュレートの 2048x1536p にするよう指示したことになります。

256x224 の例を 4:3 アスペクト比で表示する場合：その比率で整数スケールした 256x224 全体が収まる解像度が必要です（上記 `#!ini vscale_mode=1` の説明どおり）。2048x1536 が各方向の最大です。1536 は 7×224 にあと少し届かないため、MiSTer は垂直倍率に 6 を使い、1344 になります。水平解像度は 4:3 を維持するため、256 は別の整数倍率 7 でスケールして 1792 になります（水平と垂直の倍率が同じとは限りません）。確認には[アスペクト比計算ツール](https://andrew.hedges.name/experiments/aspect_ratio/){target=_blank}が便利です。

大掛かりに見えますが、vscale_mode=4 がすべての計算をやってくれます。

vscale_mode=4 は結果がまちまちかもしれません。たとえば PSX コアの解像度変化は完全な再同期を引き起こし、違和感を覚える人もいます。

#### vscale_mode=5（ディスプレイのアスペクト比を維持する整数解像度スケーリング）

`#!ini vscale_mode=4` と同様に動きますが、コアのアスペクト比を無視して、画面のアスペクト比に収まる整数スケール解像度だけを計算します。たとえば 1920x1200 ディスプレイ（16:10 アスペクト比）で `#!ini video_mode=1920,1200,60` を使っている場合、16:10 は変わりません。一部のコアで特定ディスプレイを横方向に埋めたい場合や、より高い解像度に対応する 31 kHz コンピューターモニターでコンソールコアを 4:3 に収めたい場合に便利です。
